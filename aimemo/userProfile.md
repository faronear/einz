## 网络环境与翻墙能力

- **老板有翻墙能力，随时可开**（2026-09-14 自述）：本机装有 **Tailscale**，可开 **exit node**
  走海外出口。需要访问海外站点/服务（含墙外自建服务）时，**直接请老板开 Tailscale exit node**，
  不用自己绕。
- **`git.tic.cc` 在美国机房**（自建 Gitea）→ 大陆直连**只有间歇性可用**：典型症状是
  `LibreSSL SSL_connect: SSL_ERROR_SYSCALL in connection to git.tic.cc:443`（TLS 握手阶段就被打断），
  `curl` 得到 `http=000`，偶尔某一次能通。**push/pull/核实远端前先确认已翻墙**，
  否则会出现"push 好像成功了但随后核实全失败"的假象。
- 其他：海外 dev 站点常超时/被墙 → 优先走国内镜像（TUNA 等）或让老板开代理；
  本机 brew cask 已坏，装工具优先下 tar.gz。

## 偏好与要求

- 重视**隐私与安全**：Einz 项目坚持 E2EE、Server 不存明文、设备密码学身份。
- 重视**简单性**：不为两个用户引入分布式复杂度（明确排除 K8s / 微服务 / PostgreSQL 等）。
- 决策风格：愿意接受逐条讨论与选项确认（2026-08-28 架构评审时四项决策全部逐项拍板）。
- 授权：项目内所有目录、文件读写权限；允许大幅删改 memo 文档。
- 开发节奏（2026-09-04）：**每次修改 app 代码后自动在模拟器重启验证**（flutter run `--pid-file` 常驻 + `kill -USR2` 热重启）；原生层改动（podspec 等）需完整重建。
- **UI 验证分工（2026-09-13）**：界面改动由**老板上真机自测**，我不代测；改完只做
  `flutter analyze` 保证能编译，然后交付。老板常会明确说"不要测试，让我来测"。
- **goldens 态度（2026-09-13）**：开发期 UI 改动频繁，主动放弃 golden 截图测试
  （已加 `-Dgolden=true` 开关，日常整文件 skip）。**不要**主动去跑/修/更新 goldens，
  等 UI 冻结或老板要求再开。老板也很在意 AI 的 token 消耗，倾向砍掉"收益不抵成本"
  的自动化环节——提方案时可以顺带说明 token 成本。
